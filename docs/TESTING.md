# 테스트 규약

테스트 코드를 작성·수정하기 전에 이 문서를 읽고 따른다.
프로젝트 고유의 예외는 `docs/PROJECT.md`에 기술한다.

## 이름 규칙

- 테스트 함수 이름은 **한글**로 작성한다. pytest는 `pyproject.toml`의 `python_functions` 설정으로 이 이름들을 수집한다.
- 형식: `성격_대상_동작`. 대상은 함수 이름 또는 관심사 단위(예: `하루상한`, `댓글길이`).
  묶을 단위가 없으면 `성격_동작`.
- 대상은 **같은 대상끼리 뭉치게** 하는 것이 목적이다. 정렬했을 때 덩어리가 보여야 한다.
- 성격 접두어는 아래 셋 중 하나만 쓴다. ⚠ 다른 이름으로 시작하면 **수집되지 않아 조용히 빠진다.**

| 접두어 | 대상 |
|---|---|
| `기능` | 정상 범위에서 의도대로 동작하는가 |
| `예외` | 잘못된 입력에 예외를 던지는가 |
| `경계` | 끝값·전환점에서 정확한가 (0, 딱 맞는 값, 초과, 날짜가 바뀌는 순간) |

예시
```
기능_허용범위_지정채널_영상은_통과한다
기능_댓글길이_40자_이상_120자_이하면_통과한다
예외_설정_채널목록이_비면_예외
경계_하루상한_10번째는_허용되고_11번째는_거부된다
경계_하루상한_자정이_지나면_다시_센다
경계_영상당1개_같은영상_두번째_게시는_거부된다
```

- 테스트 파일은 대상 모듈 단위로 나눈다: `tests/test_rules.py`, `tests/test_store.py`.
- 성격별로 골라 돌릴 때는 이름으로 거른다: `uv run pytest -k 경계_`

## 주석

- 각 테스트 함수에 **목적**을 docstring으로 쓴다.
- 테스트 로직도 주석으로 간단히 설명한다.

## 작성 원칙

- 새 판정 로직은 단위 테스트로 커버한다.
- **회귀는 테스트로 못박는다.** 버그를 고치면 같은 버그를 잡는 테스트를 먼저 추가한다.
- **쓴 테스트는 반드시 망가뜨려 본다.** 구현을 일부러 깨서 **빨간불이 뜨는 것을 본 뒤에야**
  그 테스트를 믿는다. 초록불만 확인한 테스트는 지키는 것이 없을 수 있다.
- 테스트 하나에 검증 대상 하나. 여러 성질을 한 함수에 섞지 않는다.
- **현재 시각에 기대지 않는다.** 시각이 판정에 들어가면 테스트가 시각을 인자로 넘긴다.
- 단위 테스트는 **네트워크·브라우저·LLM을 부르지 않는다.** 그것들이 필요한 확인은 아래 「수동 확인」이다.

## 수동 확인 — 자동 테스트가 못 보는 것

브라우저 게시·YouTube API·LLM 응답은 외부에 기대므로 단위 테스트로 지키지 않는다.

- 바꿨으면 **본인 테스트 영상에 실제로 한 번 게시**해 확인한다. 지정 채널 영상으로 확인하지 않는다.
- 무엇을 수동으로 확인했고 무엇을 안 했는지 보고에 적는다.

## 검증

- `uv run pytest` 전체가 그린이고 `uv run ruff check`가 깨끗해야 완료로 보고한다.

## 판단이 필요할 때

- 이 규약과 충돌하는 판단이 필요하면 임의로 정하지 말고 사용자에게 묻는다.
