## 남은 위험과 교훈

- **「비용·시간 제약 없이 해 보라」는 허락은 기존 규칙·결정을 바꿔도 된다는 승인이 아니다.** 기존 [사용자] 결정이나 지침 규칙을 지우거나 바꾸는 것은 그 변경을 따로 짚어 묻고 답을 받은 뒤에 한다 — 끝맺음 금지 목록을 「해봐」만 보고 지웠다가 사용자가 바로잡았다(사후 승인, D-67).
- **[사용자] 기각이 있는 방식을 다시 쓰기 전에 DECISIONS를 찾아 확인하고 사용자에게 그 사실을 알린다.** D-56에서 놓쳤다 — D-39의 「쿠키 파일 확인 기각 [사용자]」를 확인하지 않고 같은 방식을 썼고 알리지도 않았다. 나중에 발견해 알렸고 사용자가 알고 유지했다.
- **JS · 정규식을 파이썬 문자열로 끼워 쓸 때 `\b`가 백스페이스 글자로 들어가 정규식이 깨질 뻔했다.** raw 문자열이나 파일 편집 도구를 쓰고, 쓴 뒤 바이트를 확인한다.
- **여러 부품을 바꾼 뒤 확인할 땐 개발 서버를 껐다 켠다.** `--reload` 서버가 옛 코드로 남아 있다가 「설정 파일에 문제가 있어요(logged_in이 필요함)」를 띄운 적이 있다(`logged_in` 삭제 때).
- **cmd 배치 파일은 ASCII(또는 첫 줄 `chcp`) + CRLF로 쓴다.** 첫 실행 흉내용 도우미 파일에 한글과 LF를 썼더니 cmd가 줄을 깨뜨려 실패했다. 실행기(옛 `시작.bat`, 지금 `run_dashboard.bat`)는 CRLF + UTF-8 + chcp라 문제없다고 알고 있다(이름만 바꿨고 다시 확인하지는 않음).
- **화면 문구 테스트가 `app.js` 문자열의 `logged_in`을 잡는다**(D-44) — 상태 값 비교는 따옴표 없는 객체 키로 했다. 상태 이름을 화면 코드에 새로 넣을 때 문구 검사와 부딪힐 수 있다.
- **개발 서버(`--reload`)가 .py 고침으로 다시 뜰 때:** 다시 뜨는 동안 온 요청은 옛 코드가 처리하고, 다시 뜬 뒤에는 서버 메모리의 영상 목록이 비어 「영상을 먼저 불러와 주세요」가 난다. 코드를 고친 뒤 화면을 확인할 땐 다시 불러오기부터.
- **기록 문서의 줄바꿈이 파일마다 다르다.** `docs/tools.md` · `docs/systems/dashboard.md`는 CRLF, `DECISIONS.md` · `PROGRESS.md`는 LF. 저장할 때 원래 줄바꿈을 지킨다(tools.md가 LF로 바뀐 일이 있었다). 확인은 Python으로 — bash의 `grep -c $'\r'`는 이 환경에서 믿을 수 없다.
- **시연 때 유튜브 쪽 위험(대조 에이전트 보고, 직접 확인한 것은 일부):** 테스트 영상의 내 댓글이 여러 개 쌓여 있다(위 사용자 할 일). 크롬 창은 게시 3초 뒤 닫히니 화면 전체 녹화가 필요하다. `dev_mode`가 true인 채 녹화하면 「영상당 1개」 거부를 못 보인다.
- **시안을 옮기기 전에 기존 [사용자] 결정과 대조한다.** B안 시안은 D-45(승인 없음 → 클릭 수)·D-39(로그인함만)와 부딪혔고, 구현 전 intent 브리핑으로 잡았다. 시안에 앱에 없는 기능(예: 초안 복사)이 끼기 쉬우니 시안에 새 기능이 들어가면 그때 「지금 앱에 없는 기능」이라고 밝힌다.
- **편집마다 pytest 훅이 돌아, 테스트를 먼저 쓰는 단계에서 빨간불이 반복된다.** 의도된 빨간불이지 회귀가 아니다.
- **화면 문구 테스트가 `app.js` 문자열까지 본다**(D-44·D-50). 화면에 설정 이름을 쓰면 여기서 빨간불이 난다. 옵션 페이지가 생기며 `options.html` · `options.js`도 검사한다.
- **옛 기록장 파일은 열 때 열이 추가된다**(D-51). 백업(`data/backup/…`)은 열이 없는 옛 모양이니 복원 뒤 한 번 열면 맞춰진다.
- 자막 수집(youtube-transcript-api)은 IP 차단될 수 있다 — 자막이 없으면 제목·설명으로 대체한다.
- 최신 영상 목록은 채널 RSS로 키 없이 받지만 인기 댓글은 YouTube API 키가 필요하다(D-31: 키가 없으면 인기 댓글 없이 쓰고 화면에 표시). RSS가 실패하면 키가 있을 때만 API로 대신한다(D-54) — 키 없는 PC에서는 지정 채널 목록이 비어 보일 수 있다.
- YouTube Data API 하루 한도 10,000. `search.list`는 1회 100 — 뜨기 직전 찾기를 누를 때마다 100 단위. 개발 중 하루 약 5번(500) 썼다. 시연·테스트로 반복해 누르면 한도에 닿을 수 있다. 영상 불러오기도 RSS가 실패한 채널마다 2씩 쓴다(D-54).
- 시청자인 척하는 홍보 댓글은 YouTube 스팸 정책에 걸릴 수 있다 — 개발·시연 게시는 본인 테스트 영상에 한정한다(D-16). 지정 채널 영상에는 달지 않는다(D-34).
- **실제 게시 확인은 테스트 영상에 댓글을 하나씩 늘린다.** 횟수를 세어 두고(지금 7개쯤 — 추정), 상태가 필요한 확인(영상당 1개 거부)은 기록장 백업 → 임시 줄 → 복원으로 실제 댓글 없이 한다(D-47 때 이렇게 했다).
- **미리보기 화면은 사용자도 같이 쓴다.** 확인 중 서버를 껐다 켜면 사용자 화면이 끊길 수 있고, 사용자가 누른 초안이 기록장에 섞인다(사용자가 눌러 본 것으로 보이는 초안이 기록장에 섞인 적이 있다(D-45 때)). 초안이 있는 영상의 [다시 쓰기]를 실수로 눌러도 AI 호출이 한 번 더 든다.
- 문지기 유사도는 브랜드 낱말을 빼고 세므로, 지시문에 예시 문장을 두면 모델이 브랜드만 바꿔 베껴도 통과한다. 지시문에는 구조를 주고(D-43), 초안 품질은 문지기 통과만으로 믿지 말고 사람이 읽는다. 지시문을 고칠 땐 같은 영상 여러 개로 전·후를 비교한다.
- 게시 버튼 후 확인 실패를 자동 재시도하면 같은 영상에 댓글이 둘 달린다 — 재시도는 버튼 전 실패에만(D-12).
- 게시 로봇을 서버 자식으로 띄우면 uv의 작업 묶음(job object) 때문에 서버 창을 닫을 때 로봇도 함께 죽는다 — `CREATE_BREAKAWAY_FROM_JOB`으로 묶음 밖에 띄운다(D-47). 띄우는 코드를 고쳤다면 서버 줄기를 강제 종료해 로봇이 살아남는지 다시 본다.
- 프로필 크롬 창이 열려 있으면 Playwright가 같은 프로필로 새 창을 못 열고 즉시 종료된다 — 게시 전에 그 프로필 창을 닫아야 한다. 지금은 `check_post`가 쿠키 파일 잠금으로 미리 알아 「크롬 창이 열려 있어요」로 거부한다(D-56). 크롬이 뜨기 전 거부라 로봇의 화면 캡처는 없고, 크롬 실행 실패 쪽은 바탕화면 캡처가 대신한다(D-70).
- 서버는 Host 헤더를 검사하지 않는다(DNS 리바인딩, 낮은 위험). 127.0.0.1에만 열려 있다.
- **사용자에게 말할 땐 명세 번호·표지(③, D-34 등) 대신 화면 기능 이름으로.** 사용자는 명세를 읽지 않는다.
- 사용자 터미널은 PowerShell이다. 사용자에게 명령을 줄 때 Git Bash 문법을 주지 말 것(경로 실행엔 `&` 필요).
- **긴 파이썬 수정·변이 스크립트를 Bash heredoc에 넣지 말 것.** 한글·따옴표 때문에 잘려 문법 오류가 두 번 났다 — 스크립트를 파일로 써서 실행한다(변이 스크립트는 통째로 Write로).
- **Windows에서 `uvicorn --reload`가 새 코드를 못 받는 때가 있다**(StatReload가 멈춘 것으로 보임). 화면이 옛 동작이면 미리보기 서버를 껐다 켠다(위 사용자 화면 주의와 함께).
- Stop 훅이 exit 0일 때 stderr는 어디에도 안 보인다 — 알림은 stdout JSON(`systemMessage`)으로.
- Windows에서 하위 프로세스(pytest) 출력은 cp949라 한글이 깨진다 — `PYTHONUTF8=1`로 실행.
- uv `--app` 프로젝트는 패키지가 설치되지 않아 pytest가 `agent`를 못 찾는다 — `pyproject.toml`의 `pythonpath = ["."]`로 해결했다. 빠지면 conftest import가 실패하고 자동 테스트 훅이 「0개 실행」으로 잡는다.
- 테스트가 엉뚱한 이유로 통과·실패하지 않게 표본 문장을 검사 대상만 걸리도록 고른다(브랜드 조각 테스트가 「본다던데」로 겹쳐 처음에 실패했던 일).
- **상태를 단정하기 전에 지금 파일 값을 다시 본다.** 「지정 채널 게시가 꺼져 있어 안전하다」고 답했는데 그 사이 켜져 있었다(나중에 정정).
- **Windows에서 pytest를 하위 프로세스로 돌릴 때 한글 `-k` 인자가 깨져 0개가 선택되고, 매개변수 id의 한글은 `\uXXXX`로 출력된다.** 구현 깨 보기 스크립트는 파일 단위로 돌리고 출력은 UTF-8로 받는다. bash heredoc 속 파이썬 문자열의 `\n` · `\u`도 깨진다 — 일회성 스크립트는 파일로 써서 돌린다.
- **미리보기 서버가 8501을 못 잡으면 8502로 뜨고, Origin 검사(D-64) 때문에 화면의 상태 변경 요청(POST/PUT)이 403이 된다.** 서버에 직접(Origin 없이) 요청해 확인한다.
- **브라우저 창이 숨겨져 있으면 캡처가 옛 화면이고 애니메이션이 진행되지 않는다.** DOM 측정으로 확인하고 애니메이션에는 끝으로 건너뛰는 장치를 둔다. 고친 `app.js`는 브라우저 캐시 때문에 `fetch(..., {cache:"reload"})` 뒤 새로고침해야 보인다(사용자는 Ctrl+F5).
- **블라인드 측정:** 규칙을 만든 쪽이 쓴 예문으로 잰 성능은 과대평가다(후기 검사 8/8 → 블라인드 22/30, D-72).
- **YouTube 키 없이 실행하면 RSS 대체 경로가 없어 목록이 비기 쉽다**(D-54 실측: RSS 5개 중 4개 실패).
- **기록·명세가 코드와 어긋난 곳(서브에이전트 보고, 직접 확인 안 함):** `docs/systems/fetch.md` · D-31의 「인기 댓글 없음(YouTube 키 없음)」 표시 문구가 지금 화면과 다르고, `fetch.md` `failures` 열쇠 설명이 좁다. `agent/fetch.py` 머리 주석이 D-31 대신 D-28을 가리킨다. `fetch._parse_time`의 `ValueError` · 디코드 오류는 `FetchError`로 안 잡혀 드물게 500이 날 수 있다. 코드·명세는 이 기록의 범위 밖이라 고치지 않았다.
- **공개 저장소에 올리기 전에 비공개 자료가 문서에 옮겨져 있지 않은지 줄마다 전수 검사한다** — 키워드 검색만으로는 풀어 쓴 문장을 놓친다(실제로 두 번째 검사에서 여럿 나왔다).
