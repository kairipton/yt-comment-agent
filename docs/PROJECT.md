# 유튜브 댓글 에이전트 프로젝트 지침

**이 프로젝트 전용**의 개요·규칙·구조만 둔다.<br>
사용자에게 설명할 때는 기획자도 알아들을 수 있을 만큼 쉽게 설명하는 것을 전제로 한다.

파이썬 프로젝트 공통 지침은 이 저장소의 `CLAUDE.md`가 진다. **같은 규칙을 두 곳에 적지 않는다.**

⚠ **여기는 「무엇을 하라」만 둔다.** 경위는 커밋 메시지가 진다.

누가 정했는가는 표지로 밝힌다 — `[요구]`(요구사항으로 정해졌다 — 바꿀 수 없다) ·
`[사용자]`(사용자가 정했다 — 뒤집기 전에 묻는다) · `[에이전트]`(구현하며 정했다).

## 개요

**사용자 컴퓨터에서 실행하는 대시보드**다 [요구]. 웹에 올린 페이지는 크롬 프로필을 열 수 없기 때문이다.
지정 채널 영상에 맥락에 맞는 댓글을 달아, 읽은 사람이 **「운명원」에서 연애 사주를 보고 싶어지게** 하는 것이 목적이다.

화면은 세 칸이다 [요구].

| 칸 | 동작 |
|---|---|
| ① 영상 불러오기 | 버튼 한 번에 지정 채널 5개의 최신 영상을 썸네일·제목·채널·올린 날짜로 표시 |
| ② 영상 선택 | 고르면 AI가 정리한 「영상 속 고민 한 줄」과 「댓글 초안」 표시 |
| ③ 댓글 달기 | 크롬 프로필이 열리며 한 글자씩 타이핑 → 게시 → 내 댓글 확인까지 화면에 보이게 진행 |

## 운영 규칙 — 코드에서 강제한다 [요구]

- **허용 범위:** 지정 채널 5개의 영상과 본인 테스트 영상에만 게시한다. 직접 입력한 링크도 채널을 확인해 막는다.
  - `config.yaml`의 `channel_posting`이 `false`면 지정 채널 영상에도 게시하지 않는다 — 테스트 영상에만 단다. 지정 채널 영상에 실제로 달지는 사용자가 정한다 [사용자] (D-16·D-34). `dev_mode`와 따로 돌아 시연 때 `dev_mode`를 꺼도 풀리지 않는다.
  - 뜨기 직전 영상은 지정 채널 영상이어도 게시하지 않는다 — 초안까지만(고정 규칙, D-22).
- **영상당 댓글 1개.** 한 영상에는 계정 하나만 댓글을 단다.
  - 본인 테스트 영상(`config.yaml`의 `test_video_ids`)은 `dev_mode: true`일 때만 이 규칙의 예외다. 시연 녹화 때는 끈다. 하루 상한은 언제나 적용한다 [사용자] (D-17·D-23).
  - `dev_mode`를 켜고 단 테스트 영상 게시는 나중에 `dev_mode`를 꺼도 「영상당 1개」에 세지 않는다 — 그래서 시연(`dev_mode` 끔) 때 테스트 영상의 첫 게시는 통과하고 두 번째가 막힌다 [사용자] (D-23). 반대로 `dev_mode`를 켜고 만든 시도를 끈 뒤에 띄우면 예외를 쓰지 않는다(D-35).
- **하루 게시 상한**(기본 10개).
- **기록:** 어느 영상에 · 어느 프로필로 · 무슨 댓글을 · 성공/실패를 시간순으로 보여 준다.

## 댓글 규칙 [요구]

- 자막(없으면 제목·설명)과 인기 댓글을 읽고 **영상이 다루는 연애 고민을 먼저 정리한 뒤** 댓글을 쓴다.
- 영상을 본 시청자의 페르소나로 쓰고, 운명원 연애 사주를 보고 싶어지게 유도한다.
- 40~120자 · 영상 속 구체적 장면이나 말을 하나 이상 언급 · 영상마다 다르게.
- **금지:** 링크 · 해시태그 · 운명원을 직접 이용해 본 것처럼 지어낸 후기.

## 브라우저 자동화

- 크롬 프로필은 **별도 user-data-dir 폴더**로 연다(`launch_persistent_context`) [요구]. 평소 쓰는 기본 프로필은 자동 제어가 막혀 있다.
- 프로필별 구글 로그인은 **사용자가 수동으로 한 번** 한다. 자동화 창에서 로그인을 시도하지 않는다 [에이전트].
- 유튜브 **한국어 화면**에서 작동해야 한다 [요구].
- 진행 상태(프로필 여는 중 → 입력 중 → 게시 완료 · 댓글 보기)를 대시보드에 표시하고,
  실패하면 **이유와 화면 캡처**를 남긴다 [요구].

## 개발 구조

- 설정의 주인은 `config.yaml`이다. 채널 ID·프로필 경로·상한 값을 코드에 하드코딩하지 않는다.
- **허용 범위·상한·댓글 검증 같은 판정은 화면(web/)·서버 API(app.py)·브라우저(Playwright) 코드에 쓰지 않는다.**
  입력 값과 현재 시각을 받아 판정만 돌려주는 함수로 두어, 브라우저·API 없이 테스트한다 [에이전트].
- **판정 부품은 결정론이다 — 같은 입력이면 언제나 같은 판정** [사용자]. 입출력·현재 시각·난수에 손대지 않고,
  필요한 값은 부르는 쪽이 인자로 넘긴다. `tests/test_architecture.py`가 import와 시각 읽기 호출을 검사해 강제한다.
  AI 초안은 매번 달라질 수 있으므로, 초안이 아니라 **초안을 거르는 판정**이 결정론을 진다.
- 화면(`app.py`)과 부품(`agent/`)을 나눈다. 화면은 부품을 부르기만 한다 [사용자].
- **영상당 1개는 DB 제약으로도 막는다** — 게시 버튼을 누른 시도 중 예외(dev_mode의 테스트 영상)가 아닌 줄에만 영상 id를 유니크 열에 채우고, 나머지 줄은 비워 둔다(D-05). 판정 함수에 실수가 있어도 저장에서 거부되게 한다 [에이전트].
- 화면은 HTML 페이지(web/) + 파이썬 서버(app.py, FastAPI)다 [사용자]. 실행: `uv run uvicorn app:app --port 8501`.
- 게시(Playwright)는 서버와 **별도 프로세스**로 돌린다. 진행 상태는 DB를 거쳐 서버가 읽고, 화면은 서버에 물어 갱신한다 [에이전트].
- 런타임 데이터(DB·실패 캡처)는 `data/`에 두며, 이 폴더는 Git에 올리지 않는다.

## 시스템 명세

- 작업 시작 전 `docs/system-map.md`를, 코드 전 대상 시스템의 명세 `docs/systems/<시스템>.md`를 읽는다.
  명세가 없으면 먼저 쓰고 사용자 확인을 받는다.
- ⚠ 명세를 새로 쓰거나 꼴을 바꾸기 전에 `docs/SPEC-WRITE-GUIDE.md`를 읽는다.
- ⚠ **요구사항이 언제나 이긴다.** `[요구]` 항목과 명세가 어긋나면 코드를 자동으로 고치지 말고 사용자에게 올린다.
- 운영 규칙·댓글 규칙을 건드리거나 여러 시스템에 걸치는 작업은 착수 전에 `intent` 에이전트의 브리핑을 받는다.
- 시스템 하나가 끝나면 `docs/system-map.md`의 명세 칸을 채운다.

## 기록 — 세션 인수인계

- **새 세션은 `docs/PROGRESS.md`부터 읽는다.**
- 기록 문서 셋(`PROGRESS` · `DECISIONS` · `tools`)은 직접 고치지 않고 `/record`로 갱신한다.
- 작업 단위가 끝났을 때, 그리고 세션을 마치기 전에 `/record`를 돌린다.
- 훅·에이전트·커맨드를 늘리면 `docs/tools.md`에 오르게 `/record`를 돌린다. 설명은 파일 머리 주석에 쓴다.
