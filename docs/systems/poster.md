# poster — 게시 로봇

서버가 만든 **게시 시도 한 줄**을 받아, 크롬 프로필을 열고 한 글자씩 타이핑 → 게시 → 내 댓글 확인까지 한다.
서버와 **별도 프로세스**로 돈다(D-06): `python -m agent.poster <attempt_id>`. 화면은 기록장의 상태를 0.5초마다 읽어 진행을 보여 준다.
운영 규칙은 서버가 이미 검사했어도 **로봇이 스스로 다시 검사한다** — 화면을 거치지 않고 로봇을 직접 띄워도 규칙이 지켜진다.

## 구성요소

```python
class Rejected(Exception)                        # 게시 전 거부 — 이유 목록. 브라우저를 열지 않거나, 버튼을 누르지 않는다
class PostFailed(Exception)                      # 브라우저 단계 실패 — 이유 · 캡처 경로 · 취소인가(사용자가 창을 닫음)

def check_post(video: VideoItem, text: str, profile: str, exempt: bool, settings: Settings, store: Store,
               now: datetime) -> Verdict
    # 게시 검사 한 곳: 허용 범위 · 예외 표시 · 영상당 1개 · 하루 상한 · 초안 일치 · 댓글 규칙 · 프로필. 서버(③)도 이것을 부른다
def preflight(attempt: Attempt, settings: Settings, store: Store, now: datetime) -> Verdict
    # 게시 전 재검사 = check_post(시도 줄의 값)
def run(attempt_id: int, settings: Settings, store: Store, post: PostFn, now: Callable[[], datetime]) -> int
    # ③ 한 번 누름의 전체 흐름: 시도 잡기 → 잠금 → 검사 → 게시 → 버튼 전 실패면 새 줄로 자동 재시도. 종료 코드
def post_comment(profile: Profile, video_id: str, text: str, shot_prefix: Path,
                 on_status: Callable[[PostStatus], None], on_typed: Callable[[int], None]) -> str
    # 실제 브라우저(Playwright). 열기 → 로그인 확인 → 댓글 창 → 타이핑 → 버튼 → 확인. 댓글 링크를 돌려준다
    # on_typed: 15글자 묶음을 칠 때마다 지금까지 친 글자 수 — run이 store.set_typed로 적는다(화면의 「86자 중 45자」)
def comment_url(href: str, video_id: str) -> str | None  # 댓글 시각 링크(href)에서 `watch?v=…&lc=…`를 만든다. lc가 없으면 None
def launch_reason(message: str) -> str           # 크롬 실행 오류를 한국어 이유로(「프로필 창이 이미 열려 있어요」 등)
def desktop_shot(prefix: Path, step: str) -> Path | None  # 바탕화면 전체 캡처 — 크롬을 띄우지 못해 찍을 브라우저 화면이 없을 때. 실패하면 None
def main(argv: list[str]) -> int                 # 진입점: 설정·기록장을 열고 run을 부른다
```

`PostFn`은 `post_comment`와 같은 모양의 함수다. 테스트는 브라우저 대신 정해진 결과를 내는 가짜를 넣는다.

## 동작

### 게시 대상 제한 — 채널 게시 스위치 (D-16 · D-34) [사용자]

- config에 **`channel_posting`** 스위치를 둔다(지금 값 `false`). 꺼져 있으면 지정 채널 영상은 전부 거부 — 「지정 채널 게시가 꺼져 있어요」. **테스트 영상만** 게시된다.
- `dev_mode`와 따로 돈다 — `dev_mode`를 꺼도 이 스위치가 꺼져 있으면 지정 채널 영상에는 달리지 않는다.
- 판정은 `guard.check_target`이 한다(인자 `channel_posting`을 더함). 서버(③ 누를 때)와 로봇(preflight) 두 곳이 같은 판정을 쓴다.
- AI 명령을 막는 훅은 두지 않는다 [사용자] — 명령 문자열로는 새는 곳이 많아 효과가 작다.

### 게시 전 재검사 — `preflight`

브라우저를 열기 **전에** 본다. 하나라도 걸리면 상태 `REJECTED` + 이유 전부, 브라우저를 열지 않는다.

| 검사 | 쓰는 것 |
|---|---|
| 허용 범위 | `guard.check_target(video, 지정 채널, 테스트 영상, channel_posting)` |
| 예외 표시 | `guard.check_exempt(시도의 exempt, guard.is_exempt(지금 dev_mode))` — 시도 줄을 만든 뒤 `dev_mode`를 껐으면 예외를 쓸 수 없다(시연 중 테스트 영상에 둘 달리지 않게) |
| 영상당 1개 · 하루 상한 | `guard.check_quota(store.has_posted, 시도의 exempt, store.submitted_count(guard.quota_window(now, store.last_quota_reset())), daily_max)` — 오늘(초기화가 있었으면 그 뒤) |
| 초안 일치 — **모드와 무관** | `guard.check_draft(store.get_draft, 시도의 댓글)` — 그 영상의 저장된 초안이 있고 · 불합격 이유(`issues`)가 없고 · 시도의 댓글이 초안 댓글과 같다. 불합격 초안이나 바뀐 글이 자동 모드·직접 실행으로 새지 않게 |
| 프로필 | 시도의 프로필 이름이 config `profiles`에 있고, 지금 그 프로필이 유튜브에 로그인되어 있다(`chrome.login_state`). 「로그인 필요」면 「[프로필 관리]에서 로그인해 주세요」, 「크롬 창 열림」이면 「그 프로필의 크롬 창을 닫고 다시 눌러 주세요」로 거부 — 크롬을 열지 않는다 |
| 댓글 규칙 | `guard.check_text` — 글자 수 · 링크 · 해시태그 · 운명원 언급 · 지어낸 후기 · 다른 영상 댓글과 유사도(`store.comparable_texts`) |

- 「재료와 겹침」(영상 속 장면을 짚었나)은 자막이 있어야 볼 수 있어 초안 단계(draft)에서만 본다.
- 판정은 전부 guard 함수로 한다 — 로봇 코드에 비교식을 직접 쓰지 않는다.

### 한 번 누름의 흐름 — `run`

1. **시도를 잡는다:** 기록장에서 상태가 `QUEUED`(대기)인 시도만 `OPENING`으로 바꾼다(한 문장으로 원자적). 이미 잡힌 시도면 **아무것도 쓰지 않고** 종료 — 같은 시도를 두 번 띄워도 남의 줄을 덮어쓰지 않는다.
2. **한 번에 하나만:** 데이터 폴더의 잠금 파일을 잡는다. 이미 잡혀 있으면 잡은 시도를 `REJECTED`「다른 게시가 진행 중이에요」. 프로세스가 죽으면 OS가 잠금을 푼다.
   하루 상한을 두 로봇이 동시에 세는 일과 같은 프로필을 두 번 여는 일을 막는다. 잠금 아래에서는 수가 늘 수 없으므로 상한은 preflight에서 한 번만 센다.
3. **멈춘 줄 정리:** 잠금을 잡았는데 끝나지 않은 다른 줄(`OPENING`~`CONFIRMING`)이 있으면, 앞선 프로세스가 죽은 것이다. 그 줄을 「프로그램이 중간에 멈췄어요」로 끝낸다 — 버튼을 누른 기록(`submitted_at`)이 있으면 버튼 후 실패, 없으면 버튼 전 실패.
4. `preflight` → 걸리면 `REJECTED`, 끝.
5. `post_comment`. 단계마다 `on_status`가 기록장 상태를 바꾼다: `OPENING` → `TYPING` → `SUBMITTED` → `CONFIRMING` → `CONFIRMED`(댓글 링크).
6. **게시 자리를 먼저 잡는다:** 로봇은 버튼을 누르기 **직전에** `on_status(SUBMITTED)`를 부르고, `run`은 기록장에 `SUBMITTED`를 적는다 — 영상당 1개 유니크 열이 여기서 채워진다(D-05).
   `DuplicatePostError`면 `Rejected`를 던지고, 로봇은 **버튼을 누르지 않고** 닫는다 → `REJECTED`.
7. **버튼 경계 = `SUBMITTED` 기록:** `SUBMITTED`를 적은 **뒤의** 실패는 클릭 자체의 오류까지 전부 버튼 후 실패로 본다 — 이미 달렸을 수 있고, 유니크 열이 채워져 있어 재시도는 어차피 거부된다.
   - 버튼 전 실패 → `FAILED_BEFORE_SUBMIT` + 이유 + 캡처. `guard.can_retry`가 허락하면 **새 시도 줄**(`retry_no + 1`, 같은 `root_id`)을 만들어 1부터(잠금은 쥔 채) 다시. 자동 재시도는 최대 2회 · 총 3번 시도(D-12).
   - 버튼 후 실패(확인 실패 등) → `FAILED_AFTER_SUBMIT` + 이유 + 캡처. 재시도하지 않는다.
   - **사용자가 크롬 창을 닫음** → 「사용자가 크롬 창을 닫았어요」, 재시도하지 않는다(취소) [사용자]. 버튼 경계에 따라 BEFORE/AFTER.
8. 예상 못 한 예외도 삼키지 않는다 — 버튼 경계로 BEFORE/AFTER를 정해 기록하고 `logging.error`, 재시도 규칙은 7과 같다. 종료 코드 1.

- **화면이 재시도를 따라가는 법:** 재시도 줄은 첫 시도의 id를 `root_id`로 갖는다. 화면은 첫 id로 묻고, 서버는 그 묶음의 **가장 최근 줄**을 돌려준다(4단계 서버 명세가 쓴다).
- 종료 코드: 0 = 게시 완료 · 1 = 실패·거부 · 2 = 이미 잡힌 시도.

### 브라우저 — `post_comment`

시제품(테스트 영상 게시 성공)의 실행 조건과 선택자를 **빠짐없이** 옮긴다:
`launch_persistent_context(프로필 폴더, channel="chrome", headless=False, locale="ko-KR", viewport=1280×900, ignore_default_args=["--enable-automation"])`.

| 단계 | 하는 일 | 실패 이유(화면 문구) |
|---|---|---|
| 열기 | 크롬 실행 → 영상 주소 → `ytd-watch-flexy` 대기(20초) | 프로필 창이 이미 열려 있어요(닫고 다시) · 크롬을 열지 못했어요 · 영상 화면을 불러오지 못했어요 |
| 로그인 확인 | 오른쪽 위 프로필 버튼(`ytd-masthead #avatar-btn`)이 있나 | 이 프로필은 유튜브에 로그인되어 있지 않아요 |
| 댓글 창 | 스크롤하며 `ytd-comments #simplebox-placeholder`를 찾아 누름 → 편집 칸(`#contenteditable-root`) 대기(10초). **이때 이미 있는 댓글들의 링크 id(lc)를 적어 둔다** — 댓글 목록이 보일 때까지 최대 5초 기다린 뒤 | 댓글 창을 찾지 못했어요(댓글이 꺼진 영상일 수 있어요) |
| 타이핑 | 편집 칸에 **한 글자씩**(`keyboard.type`, 글자 사이 70ms). 끝나면 칸의 글이 시도의 댓글과 같은지 확인 | 입력된 글이 다르게 들어갔어요 |
| 버튼 | `on_status(SUBMITTED)` → `ytd-comments #submit-button` 누름 | (거부면 누르지 않음) |
| 확인 | 글이 시도의 댓글과 같고 **링크 id가 적어 둔 것에 없는** 댓글이 나타날 때까지 기다림(20초) → 그 댓글의 시각 링크로 `comment_url` | 게시 후 내 댓글을 확인하지 못했어요 |

- 확인을 「새 링크 id」로 하는 이유: 테스트 영상에는 같은 글이 이미 달려 있을 수 있어, 글만 비교하면 이번 게시가 실패해도 옛 댓글로 「완료」가 된다.
- 비교할 때 앞뒤 공백·줄바꿈 차이는 무시한다.
- 단계가 실패하면 그 순간 화면을 `screenshot_dir/attempt-<id>-<단계>.png`로 남기고 `PostFailed`에 싣는다. 성공해도 확인 화면을 한 장 남긴다.
- **친 글자 수를 알린다:** 타이핑 중 15글자 묶음마다(진행 캡처와 같은 때) `on_typed(지금까지 친 글자 수)`. 공백 포함 코드포인트 수다. 상태는 바꾸지 않는다(`TYPING` 그대로).
- **진행 화면도 남긴다:** 영상 화면이 뜬 뒤 · 댓글 창이 열린 뒤 · 타이핑 중 15글자마다 `attempt-<id>-진행.png`를 덮어쓴다. 사용자가 크롬 창을 닫으면 그 순간은 찍을 수 없어, 닫히기 직전의 이 진행 화면을 취소 실패의 캡처로 싣는다 [사용자: 실패 시연은 「타이핑 중 창 닫기」].
- **크롬을 띄우지 못하면 바탕화면 전체를 찍는다 [사용자: 실패에는 이유와 화면 캡처를 함께 남긴다]:** `launch_persistent_context`가 실패하면(프로필 창이 이미 열려 있음 · 크롬 없음) 찍을 브라우저 화면이 없으므로 `desktop_shot`으로 화면 전체를 `attempt-<id>-실행.png`에 남긴다 — 열려 있는 크롬 창 같은 원인이 찍힌다. 다른 창도 함께 찍힐 수 있으나 이 PC의 `data/`에만 저장된다. 캡처가 실패해도 원래 실패 이유는 그대로 남는다. **규칙 검사 거부(게시 전 검사)는 찍지 않는다 [사용자]** — 크롬을 일부러 열지 않은 「막힘」이지 게시 실패가 아니다.
- 새 댓글은 보였는데 링크 id를 못 얻으면 영상 링크를 대신 남기고 `CONFIRMED` [사용자].
- 브라우저는 성공·실패 모두 **3초 뒤에** 닫는다 — 시연 영상에 확인 화면이 남게.
- 유튜브 한국어 화면: `locale="ko-KR"`로 연다. 선택자는 화면 언어와 무관한 요소 id만 쓴다.

### 다른 부품에 생기는 변경 (구현 때 각 명세를 먼저 고친다)

| 부품 | 변경 |
|---|---|
| models | `PostStatus.QUEUED`(「대기 중」) — 시도의 첫 상태. `Settings.channel_posting`. `Attempt.root_id` |
| config | 새 키 `channel_posting`(필수, 코드 기본값 없음) |
| guard | `check_target`에 `channel_posting` 인자 · `check_draft`(초안 일치) · `check_comment`에서 재료 없는 검사를 `check_text`로 떼어 냄(`check_comment` = `check_text` + 재료 겹침, 기존 테스트 유지) · `can_retry`에 취소 인자 |
| store | 시도는 `QUEUED`로 생성 · `claim(attempt_id, now) -> bool`(QUEUED→OPENING 원자적) · `root_id` 열과 `latest_in_root(root_id)` · 끝난 상태(완료·실패·거부)에서는 상태를 다시 바꾸지 않는다 · `fail_unfinished(except_id, now, reason)` |

## 정체성

- 크롬을 띄우지 못하면 바탕화면 캡처를 실패 기록에 싣는다 · 캡처가 안 되면 캡처 없이 이유만 남긴다 — `예외_게시로봇_크롬을_못띄우면_바탕화면을_찍는다` · `예외_바탕화면캡처_실패하면_없음을_돌려준다`
- 설정에 없는 프로필은 게시 전 검사에서 거부한다 — `예외_게시검사_설정에_없는_프로필은_거부한다`
- 같은 글이 게시 전부터 있었으면 그것을 새 댓글로 보지 않는다(거짓 성공 방지) · 새로 생긴 같은 글의 링크를 돌려준다 — `예외_댓글확인_전부터_있던_같은글은_새댓글이_아니다` · `기능_댓글확인_새로_생긴_같은글의_링크를_돌려준다`
- 운영 규칙에 걸리는 시도는 브라우저를 열지 않는다 — `기능_게시로봇_검사에_걸리면_브라우저를_열지_않는다`
- 채널 게시 스위치가 꺼져 있으면 테스트 영상에만 게시한다(D-34) — `기능_허용범위_채널게시가_꺼지면_테스트영상만_통과한다`
- 시도 줄을 만든 뒤 개발 모드를 껐으면 예외 표시를 쓰지 않는다 — `예외_게시로봇_개발모드를_끄면_옛_예외표시를_거부한다`
- 초기화 뒤에는 서버와 같은 구간으로 상한을 다시 센다 — `기능_게시로봇_초기화_뒤에는_상한을_다시_센다`
- 불합격 초안이나 초안과 다른 글은 모드와 무관하게 게시하지 않는다 — `예외_게시로봇_초안과_글이_다르면_거부한다` · `예외_게시로봇_불합격_초안은_자동모드에서도_거부한다`
- 버튼 직전에 자리를 잡고, DB가 거부하면 버튼을 누르지 않는다 — `기능_게시로봇_DB가_거부하면_버튼을_누르지_않는다`
- 자리를 잡은 뒤의 실패는 버튼 후 실패다 — `경계_게시로봇_자리잡은_뒤_실패는_버튼후_실패다`
- 버튼 전 실패만 새 줄로 자동 재시도하고, 2회에서 멈춘다 — `기능_게시로봇_버튼전_실패는_새줄로_재시도한다` · `경계_게시로봇_재시도는_2회까지만`
- 버튼 후 실패와 사용자 취소는 재시도하지 않는다 — `기능_게시로봇_버튼후_실패는_재시도하지_않는다` · `기능_게시로봇_창을_닫으면_재시도하지_않는다`
- 성공하면 완료 상태와 댓글 링크가 남는다 — `기능_게시로봇_성공하면_댓글링크가_남는다`
- 같은 시도를 두 번 띄워도 남의 줄을 덮어쓰지 않는다 — `예외_게시로봇_이미_잡힌_시도는_건드리지_않는다`
- 게시는 한 번에 하나만 돈다 — `예외_게시로봇_다른_게시가_진행중이면_거부한다`
- 죽은 프로세스가 남긴 줄은 다음 로봇이 끝낸다 — `기능_게시로봇_멈춘_줄을_실패로_끝낸다`
- 끝난 시도의 상태는 다시 바뀌지 않는다 — `예외_기록장_끝난_시도는_상태를_바꾸지_않는다`
- 재료 없이 볼 수 있는 댓글 규칙은 로봇이 다시 본다 — `기능_댓글검사_재료없이_링크와_지어낸후기를_잡는다`
- 로그인이 필요한 프로필, 크롬 창이 열린 프로필로는 게시하지 않는다 — `예외_게시로봇_로그인이_필요한_프로필은_거부한다` · `예외_게시로봇_프로필창이_열려있으면_거부한다`
- 크롬 실행 오류는 사용자가 알아듣는 이유로 바뀐다 — `기능_실행오류_프로필창이_열려있으면_그렇게_알린다`
- 댓글 링크는 `lc` 값을 담는다 — `기능_댓글링크_시각링크에서_lc를_뽑는다`
- 타이핑 중 친 글자 수가 기록장에 남는다 — `기능_로봇_타이핑진행을_기록장에_적는다`

## 테스트 방법

- 단위 테스트는 브라우저를 열지 않는다(TESTING.md). `run`에 가짜 `post`를 넣어 상태 순서 · 거부 · 재시도 · 잠금 · 멈춘 줄을 검사한다. 기록장은 임시 폴더의 진짜 SQLite.
- `post_comment` 자체는 수동 확인 — 테스트 영상에만: 실제 게시 1회(성공), 프로필 창을 열어 둔 채 1회(이유 확인), 로그인 안 된 프로필(yt2) 1회, 타이핑 중 창 닫기 1회(취소).
