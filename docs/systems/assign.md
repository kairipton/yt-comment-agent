# assign — 프로필 자동 배정

[댓글 달기]를 누를 때 프로필을 사람이 고르지 않고 **돌아가며** 정해 준다.
결정론 부품이다 — 같은 기록이면 언제나 같은 프로필(D-19). 입출력 없이 후보와 기록을 인자로 받는다.

## 구성요소

```python
def next_profile(candidates: list[str], history: list[Attempt]) -> str   # 후보 중 가장 오래 안 쓴 프로필
```

## 동작

- **후보** = 지금 유튜브에 로그인되어 있는 프로필(`chrome.login_state`가 `LOGGED_IN`), config 순서대로. 부르는 쪽(서버)이 걸러 넘긴다 [사용자].
  로그인 여부를 프로그램이 스스로 알아내지 않는다 — 크롬의 로그인 정보 저장소를 들여다봐야 해서 피한다 [사용자].
- **고르는 법:** 후보마다 「마지막으로 게시 버튼을 누른 시각」(`Attempt.submitted_at`)을 보고 가장 오래된 것. 한 번도 안 쓴 프로필이 먼저이고, 그런 것이 여럿이면 config 순서.
  → 유튜브1 → 유튜브2 → 유튜브3 → 유튜브1 … 로 돈다.
- 게시 버튼을 누르지 않은 시도(거부 · 버튼 전 실패)는 세지 않는다 — 실패한 프로필 차례가 넘어가 버리지 않게.
- 후보가 하나면 언제나 그것이다(지금: 유튜브1만 로그인함).
- 후보가 비면 `ValueError` — 로그인된 프로필이 하나도 없을 수 있으므로, 부르는 쪽(서버)이 먼저 비었는지 보고 「로그인한 프로필이 없어요」로 알린다.

## 정체성

- 한 번도 안 쓴 프로필부터, 그다음은 가장 오래 안 쓴 프로필 순으로 돈다 — `기능_자동배정_가장_오래_안쓴_프로필을_고른다`
- 게시 버튼을 누르지 않은 시도는 차례에 세지 않는다 — `기능_자동배정_버튼을_안누른_시도는_세지_않는다`
- 후보가 하나면 늘 그 프로필이다 — `경계_자동배정_후보가_하나면_늘_그것이다`
