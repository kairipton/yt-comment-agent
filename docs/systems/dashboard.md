# dashboard — 화면과 서버

세 칸 화면(`web/`)과 그 화면이 부르는 서버(`app.py`, FastAPI). 0단계의 가짜 데이터를 **진짜 부품 호출로 바꾼다** — 화면 배치는 0단계를 잇는다.
서버와 화면은 판정 로직을 갖지 않는다(D-18) — 게시해도 되는지는 게시 로봇과 **같은 검사 함수**(`poster.check_post`)를 불러 그 결과를 쓸 뿐이다.

## 구성요소

```python
class Services:                                    # 서버가 쓰는 부품 묶음. 테스트는 가짜로 바꿔 끼운다
    settings: Callable[[], Settings]               # 요청마다 config.yaml · .env를 다시 읽는다(키를 넣고 새로고침하면 바로 반영)
    youtube: Callable[[Settings], YouTubeClient]
    drafter: Callable[[Settings], Drafter]
    spawn: Callable[[int], Popen]                  # 게시 로봇 프로세스 띄우기: <가상환경 파이썬> -m agent.poster <id>
    now: Callable[[], datetime]
def create_app(services: Services) -> FastAPI      # 경로 등록 · 시작할 때 남은 대기 줄 정리
app = create_app(Services.real())                  # uvicorn app:app
```

- **AI 키가 없으면** 다시 쓰기 · 게시가 모두 409 「AI API 키가 설정되지 않았어요」(D-28).
- **영상 목록은 서버 메모리에 둔다** — 마지막 불러오기의 `VideoItem`(설명 포함)을 id로 찾는다. 목록에 없는 id면 404 「영상을 먼저 불러와 주세요」. 설정에 없는 프로필이면 400.
- 초안 쓰기가 실패하면(`DraftUnavailable` · `FetchError`) 503 + 이유. 화면이 ② 자리에 이유와 [다시 시도]를 보여 준다.
- 설정 파일이 잘못되면(`ConfigError`) 모든 API가 500 + 이유 목록. 화면 맨 위에 빨간 띠로 이유를 보여 준다.
- **다른 사이트의 몰래 요청을 막는다 [에이전트]:** 상태를 바꾸는 `/api/*` 요청(POST · PUT · DELETE)에 `Origin` 머리가 있으면 이 대시보드 주소(`http://localhost:8501` · `http://127.0.0.1:8501`)일 때만 받고, 아니면 403. 머리가 없는 요청(같은 PC의 도구 · 테스트)은 받는다.
- **게시 검사는 한 함수:** 서버(③ 누를 때)와 로봇(`preflight`)이 같은 `poster.check_post`를 부른다 [사용자]. 거부도 기록에 남는다 — 시연에서 「영상당 1개」가 막히는 장면이 화면과 기록에 보인다.

### 게시 로봇 띄우기 · 진행 · 대기 줄

- `spawn`은 서버를 돌리는 **같은 파이썬**(`sys.executable`, uv 가상환경)으로 `-m agent.poster <id>`를 **창 없이, 서버 창과 따로** 띄운다. 출력은 `data/poster.log`에 이어 쓴다.
- **서버 창을 닫아도 하던 게시 한 건은 끝까지 마치고 로봇이 스스로 끝난다** [사용자] — 타이핑 중간에 끊기지 않게.
- 서버는 띄운 로봇을 첫 시도 id별로 기억한다. **끝났나** = 가장 최근 줄이 끝난 상태일 때. 단 그 줄이 「버튼 전 실패」이고 로봇이 아직 살아 있으면 끝나지 않은 것으로 본다 — 곧 재시도 줄이 생기므로, 화면이 진행 확인을 멈추지 않게. 서버가 모르는 로봇(서버 재시작 전)이면 줄 상태만 본다.
- 띄우기 자체가 실패하면 그 줄을 「게시 로봇을 띄우지 못했어요」(버튼 전 실패)로 끝낸다.
- 진행을 물을 때 로봇 프로세스가 이미 끝났는데 줄이 안 끝났으면 실패로 끝낸다 — `QUEUED`면 「게시 로봇이 시작하지 못했어요」, 진행 중이면 「게시 로봇이 중간에 멈췄어요」(버튼 기록이 있으면 버튼 후 실패, `store.fail_stopped`).
- 서버가 시작할 때 남아 있는 `QUEUED` 줄은 「서버가 다시 시작되어 취소됐어요」로 끝낸다(`store.fail_queued`). 진행 중(`OPENING`~)으로 남은 줄은 다음 로봇이 정리한다(poster).

### 화면 (`web/`)

- **페이지 둘 [사용자]:** 대시보드(`index.html`)와 옵션(`options.html`). 두 페이지 머리에 [대시보드] · [옵션] 전환 링크.
- **옵션 페이지:** `config.yaml`의 값을 묶음별(동작 방식 · 크롬 프로필 · 영상 목록 · 댓글 규칙 · 제한 · 뜨기 직전 · AI 초안 · 저장 위치) 입력 칸으로 — 켜기/끄기는 스위치, 숫자는 숫자 칸, 선택지는 고르기, 채널 · 테스트 영상 · 프로필 · 금지 표현은 줄 추가/삭제. **칸마다 옛 yaml 주석의 설명을 붙인다**(설명의 주인은 이 페이지). 개발 모드는 **칸이 없다**(설정 파일로만 켠다 [사용자]). AI 모델 · 생각하는 깊이는 보여 주되 **꺼진 칸**이고 「설정 파일을 직접 고쳐야 바뀌어요」 [사용자]. [저장]은 전체를 한 번에, 걸리면 맨 위에 이유 목록 — 이유 앞의 설정 경로는 **칸 이름**(목록이면 「n번째 줄」까지)으로, 이유 안의 경로는 「칸 이름」으로 바꿔 보여 주고(설정 이름을 화면에 쓰지 않는다) 그 칸을 붉게 표시한다(문구 꼴은 config 명세). 저장 위치 칸에는 「바꾸면 새 파일·폴더를 써요(옛 기록은 옮기지 않아요)」. 댓글 작성 지침은 글 상자 + 쓸 수 있는 자리표시 안내 + 따로 [지침 저장]. 저장하지 않고 떠나려 하면 묻는다.

**배치(B안) [사용자]:** 세 칸을 위에서 아래로 쌓는다. **세 칸은 늘 다 보이고 지금 칸만 펼친다**.
- **칸 이름 [사용자]:** ① 영상 불러오기 · ② 영상 선택 · ③ 댓글 달기. ②는 고른 영상의 고민 한 줄과 초안을 보여 주는 칸이다.
- 끝난 칸은 ✓ 요약 띠: ①이면 고른 영상 썸네일·제목·채널 + [다른 영상으로 바꾸기](테두리 있는 버튼으로 눈에 띄게 [사용자])(①을 다시 펼친다 — 게시 중이어도 게시는 끊기지 않는다), ②면 「n번째 초안으로 확정」.
- 아직 안 온 칸은 점선 띠에 「무엇을 하면 열리는지」 한 줄.
- 지금 칸: 영상을 안 골랐으면 ①, 골랐으면 ②, ③을 눌렀으면(진행·결과) ③. 이 고르기는 화면 상태일 뿐 판정이 아니다.
- **②→③은 클릭을 늘리지 않는다(D-45 유지) [사용자]:** ② 초안이 보이는 동안 ③ 띠는 「프로필 고르기 + [댓글 달기]」 작은 칸이다. 누르면 곧바로 게시가 시작되고 ③이 펼쳐져 진행이 보인다.
- **단계 전환 — 두 박자 접기·펼치기 + 단계 표시 [사용자: 「1 -> 2로 넘어갈때 화면 구성이 갑자기 크게 바뀌어서 혼동이 와」 · 썸네일 이동만으로는 「아직 헷갈릴 소지가 있다」 → 헷갈리는 점 「지금 몇 단계인지 · 화면이 너무 크게 바뀜」, 방향 「접기·펼치기를 두 박자로 + 안내」]:** 칸을 바꿀 때 지금 칸이 먼저 위로 접히고(0.4초 안팎, 화면도 ① 위치로 부드럽게 올라감) 그다음 새 칸이 아래로 펼쳐진다. ①이 접히면 「고른 영상」 띠에 「영상 목록은 여기 접혀 있어요」가 붙고 띠가 잠깐 반짝인다. 세 칸 위에 **단계 표시**(① 영상 불러오기 · ② 영상 선택 · ③ 댓글 달기 — 지난 칸 ✓ · 지금 칸 강조)를 두고 스크롤해도 위에 붙어 따라온다. ②를 펼치는 동안 옛 영상의 초안은 보이지 않는다(쓰는 중 표시). 「동작 줄이기」 설정에서는 바로 바뀐다. 썸네일 이동 전환(View Transitions)은 이것으로 바꿨다.
- ③ 결과 색은 서버가 준 `tone` 하나로 고른다: done(초록 「끝났어요」) · fix(주황 「손봐야 해요」) · blocked(남색 「막혔어요」). 화면이 상태나 이유 글자를 다시 나누지 않는다.

| 칸 | 바뀌는 것 |
|---|---|
| 프로필 관리 [사용자] | 머리의 [프로필 관리 · 로그인 n개] 버튼(또는 ③ 띠의 「로그인 필요」 프로필)을 누르면 머리 아래에 펼쳐진다. 프로필마다 이름 · 상태(「로그인되어 있음」 · 「로그인 필요」 · 「크롬 창 열림 — 닫으면 확인」) · [크롬 열기](상태와 상관없이 늘). 상태는 **몇 초마다 서버에 물어 저절로 바뀐다**(`GET /api/profiles`, 2초) — 로그인하고 창을 닫으면 「로그인되어 있음」으로 바뀐다. 안내: 「[크롬 열기] → 유튜브에 로그인 → 창 닫기」 · 「댓글을 달기 전에 프로필 창은 꼭 닫아 주세요」. 실패하면 그 자리에 이유 |
| 머리 | 앞: 「오늘 남은 댓글 N개 / 상한」(= 상한 − 오늘 게시) · [프로필 관리 · 로그인 n개] · [게시 기록 보기](기록 표로 이동). 뒤: 칩 게시 모드 · 게시 대상(「테스트 영상만」/「지정 채널 + 테스트 영상」) · AI 키 · YouTube 키. 「🧪 개발 모드」 칩은 켜져 있을 때만. 개발 모드일 때만 「오늘 남은 댓글」 옆에 [초기화] — 누르면 확인 창(「기록은 지워지지 않아요」) 후 초기화. 설정 오류면 빨간 띠 + 이유 |
| ① 종류 탭 [사용자] | 전체 / 지정 채널 / 뜨기 직전 / 테스트 영상(맨 오른쪽 [사용자]), 개수 표시. 화면 안에서만 거른다(`source`). 링크로 넣은 영상은 「전체」에만. 뜨기 직전과 겹쳐 합친 줄은 「뜨기 직전」. 탭을 바꿔도 자동 모드 체크는 남는다. [뜨기 직전 영상 찾기]를 누르면 결과를 받은 뒤 「뜨기 직전」 탭으로 간다. 영상 카드를 누르면 바로 골라져 ②가 열린다 |
| ② 머리 | 한 줄기로 읽히게 줄인다 [사용자: 「약간의 다이어트」]. 썸네일(누르면 유튜브) · 제목 · 채널 · 올린 날 · 조회수(있을 때) · 「AI가 정리한 영상 속 고민」 → **[댓글을 달 수 없을 때] 주황 안내 상자**: 게시 대상이 아니면 「이 영상에는 댓글을 달 수 없어요 — 이유. 초안은 참고로 볼 수 있어요」, 규칙 불합격이면 「규칙에 맞지 않는 초안이에요」 + 이유 목록 + [다시 쓰기] 안내 → 「유튜브에 이렇게 달려요」 댓글 모양 → 그 아래 한 줄: 글자 수(마우스를 올리면 공백 제외·포함과 기준) · 「규칙 통과」(통과일 때) · 「자막 n자와 인기 댓글 n개를 읽고 썼어요」(자막 0이면 「자막이 없어 제목·설명으로 썼어요」, 인기 댓글 null이면 그 부분 생략, 옛 초안이면 생략). **오른쪽 「AI가 읽은 것」·「댓글 규칙」 상자는 두지 않는다** |
| ③ 진행 | 4단계 막대(프로필 열기 → 한 글자씩 입력 → 게시 → 내 댓글 확인)와 「지금 크롬에 입력되는 글」(친 부분 진하게, `typed`/`total`자). 프로필은 버튼 줄로 — 로그인 전 프로필은 흐리게 「로그인 전」, 누를 수 없다 |
| ③ 끝남 | 달린 댓글 모양 + [유튜브에서 댓글 보기 ↗] · [다음 영상 고르기](①을 펼친다) |
| ③ 손봐야 | 멈춘 단계 표시 · 이유 · 캡처(크게 보기). 버튼 전 실패: 「댓글은 달리지 않았어요 · 오늘 상한에 세지 않아요」 + [다시 달아 보기]. 버튼 후 확인 실패: 「게시 버튼은 눌렀어요 — 유튜브에서 달렸는지 확인해 주세요 · 오늘 상한에 셌어요」, [다시 달아 보기] 없음 |
| ③ 막힘 | 이유 · 「크롬은 열지 않았어요」. `previous`가 있으면 「먼저 단 댓글」(시각 · 프로필 · 글 · 링크가 있으면 링크). [다른 영상 고르기] |
| ① | [뜨기 직전 영상 찾기] 버튼(YouTube 키가 없으면 꺼짐 + 이유) — 결과는 「뜨기 직전」 탭으로 옮겨 「뜨기 직전 · 조회수 2,300 · 시간당 310」 표시로 보여 주고, 「검색 50개 중 n개」 안내. 「다시 측정」이 켜져 있으면 [다시 측정] 버튼. 뜨기 직전 영상은 초안까지만(「뜨기 직전 영상은 초안까지만 만들 수 있어요」로 [댓글 달기] 꺼짐). [영상 불러오기] 아래 「링크로 영상 추가」 입력칸 + [추가] — 넣은 영상은 「전체」 탭 맨 앞에 「링크로 추가」 표시로 들어가고 바로 골라진다. 지정 채널 영상이 아니면 「허용된 채널의 영상이 아니에요」로 게시 대상이 아니다(초안은 볼 수 있다). 진짜 목록(지정 채널 영상 뒤, 테스트 영상은 맨 뒤 [사용자]). 테스트 영상 표시 · 「이미 달았어요」 표시 · 게시 대상이 아닌 영상엔 이유 한 줄(초안은 볼 수 있다). 못 불러온 곳은 「못 불러온 곳 — 채널: 이유」. 다시 불러오거나 뜨기 직전을 찾으면 목록에서 사라진 영상의 자동 모드 체크를 지운다 |
| ② | 초안이 아직 없고 자동 작성이 꺼져 있으면 「아직 초안이 없어요 — AI를 부를 때마다 요금이 조금 들어요」 + [초안 쓰기]. 초안을 쓰는 동안(AI 키가 있을 때) **완성 화면의 틀을 먼저** 보여 준다 — 썸네일 · 제목 · 채널은 바로 채우고, AI가 쓸 자리(고민 한 줄 · 댓글)는 회색 줄로 비워 두고, 댓글 아래에 「AI가 영상을 읽고 초안을 쓰는 중이에요…(10~20초)」. 초안이 오면 그 자리에 글이 서서히 나타나고 칸 높이 차이는 부드럽게 바뀐다 [사용자: 「내용이 바뀌는 순간 빡 하고 갑자기 변하거든」]. AI 키가 없으면 지금처럼 한 줄 안내. 「규칙 검사」를 **진짜 결과**로 — 통과면 댓글 아래 한 줄 「✓ 댓글 규칙 통과」, 불합격이면 댓글 위 주황 상자에 이유 목록(② 머리 행) + [다시 쓰기] 안내([댓글 달기] 꺼짐). **[승인] 단계는 없다** — 「② 고르면 초안 → ③ 누르면 게시」 흐름대로, 사람이 초안을 읽고 [댓글 달기]를 누르는 것이 곧 결정이다 [사용자]. 실패면 이유 + [다시 시도] |
| ③ | 프로필 칸: 직접 고르기면 **로그인함 프로필만** 고를 수 있고, 자동 배정이면 고르는 칸 대신 「자동 배정 — 이번엔 유튜브1」을 보여 준다. 서버와 연결이 끊기면(서버 창을 닫음) 진행 확인을 멈추고 「하던 게시는 로봇이 끝까지 마쳐요 — 다시 연 뒤 기록에서 확인」을 한 번만 보여 준다. 프로필 기본값은 첫 프로필(유튜브1). 안내: 「누르기 전에 이 프로필의 크롬 창은 닫아 주세요」(프로필 추가 방법은 설명서 몫 — 화면에 설정 파일 이름·키 이름을 쓰지 않는다). [댓글 달기]는 누르는 순간 꺼진다 — 빠르게 두 번 눌러도 시도는 하나. 게시하는 동안 다른 영상을 고르면 그 게시의 진행·결과는 새 영상 칸에 그리지 않는다(끝나면 기록에 남는다). 자동 실행이 도는 동안엔 [댓글 달기]가 꺼진다. 진짜 진행 단계(프로필 여는 중 → 입력 중 → 게시 버튼 누름 → 내 댓글 확인 중 → 게시 완료). 재시도 중이면 「자동 재시도 1/2」. 실패·거부면 이유 + 캡처 그림(캡처가 없으면 「크롬이 열리기 전에 멈췄거나 창이 닫혀 캡처가 없어요」). 완료면 [댓글 보기 ↗] |
| 기록 | 시각 · 영상 · 프로필 · 댓글 전문 · 결과(상태 문구, 색은 `tone`: 끝남 초록 · 손봐야 주황 · 막힘 남색 · 진행 분홍) · 이유 · 댓글 링크 · 캡처 |

- **[댓글 달기] 버튼:** 초안이 있고(AI 키) · 그 초안이 규칙 검사를 통과했고(`issues` 없음) · 그 영상이 **게시 대상**일 때만 켜진다 [사용자]. **초안을 쓰는 중(처음 받을 때 · 다시 쓰기)에는 꺼진다** — 화면엔 기다리는 틀이 보이는데 옛 초안이 게시되는 엇갈림을 막는다 [사용자: 「예외 처리적인 성격이라면 그렇게 해」]. 게시 대상이 아니면(채널 게시 꺼짐 · 뜨기 직전 영상) 꺼진 채 이유를 보여 준다.
  「이미 단 영상」 · 「오늘 상한」은 버튼을 켜 둔다 — 누르면 크롬을 열지 않고 거부 이유가 진행 칸과 기록에 남는다.
- 화면은 판정하지 않는다 — 버튼을 켜고 끄는 근거는 서버가 준 값(`ai` · `issues` · 영상의 `postable`)뿐이다.
- 글자 수 표시는 보여 주기만 한다. 서버 문지기와 같게 코드포인트 단위로 세고, 기준은 /api/status의 값을 쓴다.

## 정체성

- 초안이 없는 영상은 게시를 409로 거부하고 시도 줄을 만들지 않는다 — `예외_서버_초안이_없으면_게시하지_않는다`
- 게시 로봇을 띄우지 못하면 그 시도를 버튼 전 실패로 끝낸다(대기 줄이 남지 않게) — `예외_서버_로봇을_못띄우면_버튼전_실패로_끝낸다`
- 그때 바탕화면 캡처를 실패 기록에 싣는다(poster 명세 「크롬을 띄우지 못하면」) — `예외_서버_로봇을_못띄우면_바탕화면을_찍는다`
- AI 키가 없으면 초안 대신 「키 없음」을 돌려주고 저장된 초안도 보여 주지 않는다(D-28) — `기능_서버_AI키가_없으면_초안_대신_키없음을_돌려준다`
- 저장된 초안이 있으면 고를 때마다 새로 쓰지 않는다 — `기능_서버_저장된_초안이_있으면_다시_쓰지_않는다`
- 게시 검사에 걸리면 로봇을 띄우지 않고 거부를 기록한다 — `기능_서버_검사에_걸리면_로봇을_띄우지_않고_거부를_남긴다`
- 검사를 통과하면 시도를 만들고 로봇을 띄운다 — 예외 표시는 `guard.is_exempt`로 붙인다 — `기능_서버_게시는_시도를_만들고_로봇을_띄운다`
- 진행 상태는 재시도 줄을 따라가고, 로봇이 살아 있으면 끝나지 않은 것으로 본다 — `기능_서버_진행상태는_재시도_줄을_따라간다` · `경계_서버_로봇이_살아있으면_실패줄이어도_끝나지_않았다`
- 로봇이 시도를 잡기 전에 죽으면 대기 줄이 실패로 끝난다 — `기능_서버_로봇이_못뜨면_대기줄을_실패로_끝낸다`
- 로봇이 시도를 잡은 뒤 중간에 죽어도 그 줄이 실패로 끝난다(버튼 기록으로 전/후) — `기능_서버_로봇이_중간에_죽으면_줄을_실패로_끝낸다`
- 서버가 다시 시작되면 남은 대기 줄이 취소로 끝난다 — `기능_서버_시작할때_남은_대기줄을_끝낸다`
- 불러온 목록에서 테스트 영상이 맨 뒤이고, 못 불러온 채널을 알린다 — `기능_서버_불러오기_테스트영상이_맨뒤이고_실패채널을_알린다`
- 목록의 「게시 대상인가」는 문지기 판정 그대로다(채널 게시 스위치 반영) — `기능_서버_불러오기_게시대상_여부는_문지기_판정이다`
- 링크로 넣은 영상은 목록에 들어가 초안을 쓸 수 있고, 허용 채널 밖이면 게시 대상이 아니다 — `기능_서버_링크로_넣은_영상은_초안을_쓰고_허용범위를_본다`
- 영상 링크가 아니면 거부한다 — `예외_서버_영상링크가_아니면_400이다`
- 고르자마자 쓰기가 꺼져 있으면 고를 때 AI를 부르지 않고, [초안 쓰기]를 눌러야 쓴다 — `기능_서버_자동작성이_꺼지면_고를때_AI를_부르지_않는다`
- 화면 문구에 설정 파일 이름·키 이름이 나오지 않는다(API 키 안내 상자만 예외) — `기능_화면문구_설정파일_용어가_보이지_않는다`
- 뜨기 직전 찾기는 기준에 드는 영상만 평균 속도 순으로 돌려주고, 그 영상은 게시 대상이 아니다 — `기능_서버_뜨기직전은_기준에_드는_것만_속도순이고_게시대상이_아니다`
- 다시 측정은 최근 속도 순이고, 간격이 짧으면 거부한다 — `기능_서버_다시측정은_최근속도순이다` · `예외_서버_다시측정_간격이_짧으면_409다`
- 자동 배정이면 서버가 돌아가며 프로필을 정하고, 직접 고르기면 로그인함 프로필만 받는다 — `기능_서버_자동배정이면_서버가_프로필을_정한다` · `예외_서버_로그인함이_꺼진_프로필은_400이다`
- 목록에 조회수와 출처를 담는다 — `기능_서버_목록에_조회수와_출처를_담는다`
- 초안에 AI가 읽은 양을 담는다 — `기능_서버_초안에_읽은양을_담는다`
- 진행 상태에 친 글자 수와 갈래를 담는다 — `기능_서버_진행상태에_친글자수와_갈래를_담는다`
- 게시 전 검사 거부면 먼저 단 댓글을 담는다 — `기능_서버_거부면_먼저단댓글을_담는다`
- 상태에 전체 프로필과 로그인 상태를 담되, 고를 수 있는 목록은 로그인되어 있는 프로필만이다 — `기능_서버_상태에_전체프로필과_로그인상태를_담는다`
- 옵션을 읽고 저장하면 다음 요청에 반영되고, 잘못된 옵션은 409와 이유다 — `기능_서버_옵션을_읽어준다` · `기능_서버_옵션을_저장하면_다음_요청에_반영된다` · `예외_서버_잘못된_옵션은_409와_이유다`
- 오늘 게시 수 초기화는 개발 모드에서만 되고, 되면 오늘 수가 0이 된다 — `기능_서버_개발모드면_오늘수를_초기화한다` · `예외_서버_개발모드가_아니면_초기화하지_않는다`
- 다른 사이트에서 온 상태 변경 요청은 막고 대시보드에서 온 것은 받는다 — `예외_서버_다른_사이트에서_온_요청은_막는다` · `기능_서버_대시보드에서_온_요청은_받는다`
- 프로필 크롬은 설정에 있는 프로필만, 게시가 돌지 않을 때만 연다 — `기능_서버_프로필_크롬을_연다` · `예외_서버_없는_프로필은_열지_않는다` · `예외_서버_게시중이면_프로필창을_열지_않는다`
- 로그인 상태 감시는 확인 결과를 그대로 돌려준다 · 로그인된 프로필이 없으면 게시를 400으로 거부한다 — `기능_서버_로그인상태_감시는_확인결과를_돌려준다` · `예외_서버_로그인한_프로필이_없으면_게시하지_않는다`

## 테스트 방법

- `fastapi.testclient`로 서버를 부르고, `Services`에 가짜 YouTube · 가짜 작가 · 가짜 `spawn`을 넣는다. 기록장은 임시 폴더의 진짜 SQLite. 네트워크·브라우저·LLM은 부르지 않는다.
- 화면은 수동 확인: 원클릭 실행 → 세 칸을 차례로 → 테스트 영상에 실제 게시 → 기록 확인. 캡처가 나오는 실패는 크롬이 열린 뒤의 실패뿐이다(로그인이 풀린 프로필 · 댓글이 꺼진 영상 등). 로그인 전으로 설정된 프로필(유튜브2)은 크롬을 열기 전에 거부되고, 프로필 창을 열어 둔 채 누르면 크롬이 뜨기 전 실패라 둘 다 캡처 없이 이유만 나온다.
